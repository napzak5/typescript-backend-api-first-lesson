# 多言語（i18n）

何を、どの言語で言うか。言語をどう決め、メッセージをどこに置くかを説明します。仕組みと
メッセージの定義は、パッケージ `@beauty-salon-shared/i18n`（`shared-i18n/`）にあります。

## 概要

- 言語は、英語（`en`）と日本語（`ja`）です。
- API は、リクエストの `Accept-Language` に合う言語で、エラー（problem details）の `title` と
  `detail` を返します。どの言語で返したかは、`Content-Language` に書きます。
- ヘッダーのないリクエスト、API の言語を 1 つも言わないリクエストには、英語で返します。
- メッセージは、すべての言語の文を 1 つの値に持ちます。片方の言語が欠けると、型の検査で
  失敗します。訳の抜けは、実行する前に見つかります。
- 成功の応答（データ）とログは、言語で変わりません。ログは、いつも英語です。

## パッケージ

```
shared-i18n/src/
├── index.ts                   # 外に出すもの: Locale、LocalizedText、textIn、localeOfAcceptLanguage
├── languages/                 # 言語とは何か、どう決めるか、すべての言語で書いた文
│   ├── locale.ts              # Locale（'en' | 'ja'）と、言語の一覧
│   ├── accept-language.ts     # Accept-Language から言語を決める
│   └── localized-text.ts      # LocalizedText、text、textIn
└── messages/                  # 言うこと。だれが言うかで分ける
    └── api/                   # API が言うこと
        ├── index.ts
        └── problems.ts        # エラーの種類ごとの title と、HTTP の層が決める detail
```

テストは、確かめるモジュールの隣にあります。

| 読み込む名前 | 中身 | 使う側 |
|---|---|---|
| `@beauty-salon-shared/i18n` | 言語、言語の決め方、すべての言語で書いた文 | バックエンドとフロントエンド |
| `@beauty-salon-shared/i18n/messages/api` | API のメッセージ | バックエンド |

- パッケージは、ほかのパッケージに依存しません。ブラウザーのものも、Node.js のものも使わない
  ので、どちらでも動きます（`tsconfig.json` の `types` は空で、`lib` は `ESNEXT` だけ）。
- 入口が 2 つあるのは、画面に API のメッセージを配らないためです。
- バックエンドの条件（`@beauty-salon-backend/source`）でも、フロントエンドの条件
  （`@beauty-salon-frontend/source`）でも、ソースから読めます。テストと開発のサーバーは、
  ビルドを待ちません。

## 言語の決め方

`localeOfAcceptLanguage(header, fallback)` が、`Accept-Language` の値から言語を決めます
（RFC 9110 の 12.5.4）。

1. ヘッダーを `,` で分け、1 つずつ、言語の範囲と重み（`;q=`）として読む。重みは 0 から 1 で、
   小数は 3 桁まで。書いていなければ 1。文法に合わない要素は、ないものとする
2. 重みが 0 より大きい範囲を、重みの大きい順に、同じ重みなら書いてある順に試す。製品の言語を
   言う最初の範囲で決まる
3. 範囲が言う言語は、タグの最初の部分で決める。`ja-JP` も `ja-Jpan-JP` も日本語。大文字と
   小文字は区別しない。製品の言語は、地域も文字の種類も付けずに書くので、RFC 4647 の 3.4 の
   Lookup が範囲を短くしていって行き着くのは、最初の部分
4. 重みが 0 の範囲は、その言語を受け取らないという意味。何も決めない。どの範囲でも
   決まらないときに、既定の言語がその言語なら、もう一方の言語にする
5. `*` は、言語を言わない。ヘッダーがないとき、どの範囲でも決まらないときは、既定の言語
   （`fallback`）。`Accept-Language` は希望で、合わないからといって、リクエストを断らない

| `Accept-Language` | 既定が英語のとき |
|---|---|
| （なし） | 英語 |
| `ja` | 日本語 |
| `ja-JP,ja;q=0.9,en;q=0.8` | 日本語 |
| `en-US,en;q=0.9,ja;q=0.8` | 英語 |
| `en;q=0.5,ja;q=0.6` | 日本語 |
| `fr-FR,fr;q=0.9` | 英語 |
| `*` | 英語 |
| `en;q=0` | 日本語 |
| `ja_JP`（文法に合わない） | 英語 |

既定の言語は、パッケージが決めません。呼ぶ側が渡します。API は英語です。

## すべての言語で書いた文

```typescript
// shared-i18n/src/languages/localized-text.ts
export type LocalizedText = Readonly<Record<Locale, string>>

export const text = (written: LocalizedText): LocalizedText => written

export const textIn = (written: LocalizedText, locale: Locale): string =>
  written[locale]
```

- メッセージは、`text({ en: '…', ja: '…' })` で書きます。`ja` を書き忘れると、コンパイル
  できません。
- 値で変わるメッセージは、値を受け取って `LocalizedText` を返す関数です。

```typescript
// shared-i18n/src/messages/api/problems.ts（抜粋）
export const problemMessages = {
  forbidden: {
    title: text({
      en: 'Forbidden',
      ja: '許可されていません',
    }),
    detail: text({
      en: 'This account is not allowed to do this',
      ja: 'このアカウントでは、この操作はできません',
    }),
  },
  routeNotFound: {
    title: text({
      en: 'Route not found',
      ja: 'ルートが見つかりません',
    }),
    detail: (method: string, path: string) =>
      text({
        en: `${method} ${path} is not part of the API`,
        ja: `${method} ${path} は、この API にありません`,
      }),
  },
  // ...
}
```

- 読む側は、言語を決めてから `textIn(message, locale)` で、その言語の文字列にします。

## API のエラーの言語

API のエラーの応答は、すべて `sendProblem`（`backend/packages/api/src/shared/responses.ts`）
が送ります。言語を決めるのも、ここだけです。

1. `languageAsked(req)`（`backend/packages/api/src/shared/language.ts`）が、リクエストの
   `Accept-Language` から、頼まれた言語を決める。既定は英語
2. `languageOf(error, asked)`（`backend/packages/api/src/shared/problem-details.ts`）が、
   そのエラーを言う言語を決める（下の表）。エラーの種類を、すべて名前で並べている
3. `toProblemDetails` が、その言語の `title` と `detail` で、problem details を作る
4. 応答に、`Content-Language`（言った言語）を付け、`Vary` に `Accept-Language` を加える

| エラー | `detail` を書く所 | 言う言語 |
|---|---|---|
| `unauthenticated`（`reason` ごとに 5 つ）、`forbidden`、`passwordRequired`、`database`、`storage` と、HTTP の層のエラー（`routeNotFound`、`malformedBody`、`unsupportedMediaType`、`bodyTooLarge`、`badRequest`、`rateLimited`、`unexpected`） | API の層（`problemMessages`） | 頼まれた言語 |
| `validation`、`notFound`、`alreadyExists`、`conflict` | ドメイン（エラーを作る所） | 英語 |

- ドメインが書く文は、まだ英語だけです。その 4 つの種類は、何を頼まれても、`title` も含めて
  全体を英語で返し、`Content-Language` を `en` にします。1 つの応答に、2 つの言語を混ぜません。
- 言語で変わるのは、`title` と `detail` だけです。`type`、`status`、`code`、`errors` の
  `field` と `rule` は、変わりません。クライアントは、文ではなく `code` と `rule` で分岐します。
- 成功の応答には、`Content-Language` も `Vary: Accept-Language` も付けません。
- 原因をログに書くとき（`database` と `storage`）の文は、英語のままです。

契約（`specs/models/_shared/common-api-patterns.tsp`）では、エラーの応答 `ProblemResponse`
に `Content-Language` のヘッダーがあり、値は列挙 `LanguageType`（`en`、`ja`）です。
`Accept-Language` は、オペレーションごとの引数にしていません。引数にすると、生成される
クライアントのすべての関数に引数が増えます。リクエスト ID の `X-Request-Id` と同じ扱いです。

`sendProblem` は、言う言語を、契約の `LanguageType` の型の変数に入れてからヘッダーに
書きます。パッケージに言語を足して、契約に足し忘れると、コンパイルできません。

```http
GET /api/v1/stylists HTTP/1.1
Accept-Language: ja-JP,ja;q=0.9,en;q=0.8

HTTP/1.1 404 Not Found
Content-Type: application/problem+json; charset=utf-8
Content-Language: ja
Vary: Origin, Accept-Language, Accept-Encoding

{
  "type": "urn:beauty-salon:problem:route-not-found",
  "title": "ルートが見つかりません",
  "status": 404,
  "detail": "GET /api/v1/stylists は、この API にありません",
  "code": "3001",
  ...
}
```

## メッセージを足す、言語を足す

API のエラーの種類を足すとき:

1. `DomainError` か `HttpError` にケースを足す（[Sum型とパターンマッチング](./sum-types-pattern-matching.md)
   の「ケースを追加するとき」）
2. `shared-i18n/src/messages/api/problems.ts` に、`title` と、API の層が書くなら `detail` を、
   両方の言語で足す
3. `problem-details.ts` の 2 つの `match` に分岐を足す。`languageOf`（`detail` をだれが書くか）と、
   `toProblem`（ステータス、`code`、文）。どちらも `.exhaustive()` なので、足すまでコンパイルできない
4. `problem-details.test.ts` の表に、両方の言語の文を足す

言語を足すとき:

1. `shared-i18n/src/languages/locale.ts` の `Locale` と `LOCALES` に足す。すべての
   `text({ … })` が、その言語の文を書くまで、コンパイルできなくなる
2. 契約の `LanguageType` に足して、`pnpm generate` を実行する。足すまで、`sendProblem` が
   コンパイルできない

## していないこと

- ドメインが書く文（検証、見つからない、すでにある、いまの状態ではできない）は、英語だけです。
- 画面の文言は、日本語だけです。画面は、`Accept-Language` を自分では決めていません
  （ブラウザーが付ける値が、そのまま届きます）。
- メールは、英語だけです。
- 合う言語がないリクエストを、406 で断ることはしません。既定の言語で返します。
